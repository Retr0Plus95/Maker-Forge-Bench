# Bench 0.7 "Everywhere" — design

Date: 2026-11-13. The owner said "Start 0.7". Until now Bench only runs from its own folder with
`dev.py`, on a PC. 0.7 lets it open projects from anywhere (a GitHub link, a folder picked in the
browser, built-in examples) and work on a phone or tablet, so it can go on the website later.

## 1. Where the files come from

`src/sources.js` gets one shape for every source: list the files, read a text file, give a picture's
address, and say whether it refreshes by itself.

- **This computer, with `dev.py`** (as now): live refresh, the "Auto-refresh on" badge.
- **A public GitHub repo:**
  - One GitHub API call lists the files: `git/trees/<ref>?recursive=1` (`HEAD` when no branch is
    given; checked, it works). GitHub allows 60 of these an hour without signing in, so Bench makes
    one per opening or refresh.
  - The files come from `raw.githubusercontent.com`. Drawings are read as text and cleaned as
    always. Photos are fetched and shown from in-memory copies (`blob:`), so the page's rules
    don't need to allow GitHub's pictures.
  - A file's fingerprint is its git hash, so "this sheet changed" notes keep working.
  - No live refresh: the badge says **From GitHub**, and clicking it refreshes (one more API call)
    and reloads only the sheets that changed.
  - A datasheet link opens the file's page on github.com.
- **A folder on this computer, picked in the browser** (for the website, where there is no
  `dev.py`). Nothing is uploaded: the browser reads the files. The badge says **From a folder**;
  to see changes, open the folder again.
- **Rules (CSP):** `connect-src` adds `https://api.github.com` and `https://raw.githubusercontent.com`.
- **`dev.py` without a folder** serves the app alone, like the website will. Tests use it.

## 2. Links

- `?repo=owner/name` opens a GitHub repo; `owner/name@branch` picks a branch, and a pasted
  `github.com/owner/name/tree/branch/sub/folder` link opens that folder.
- It combines with the links from 0.5: `?repo=…&sheet=SFE-04&part=R6` opens right at R6.
- A repo link wins even under `dev.py`.
- The part card's "Copy link" includes the repo when the project came from GitHub.
- Link parsing and the file-list mapping are pure functions, unit-tested.

## 3. The start screen

When there is no `dev.py` and no link, the stage shows **Open a project**:

- **Paste a GitHub link**, with a plain message when it isn't one;
- **Open a folder on this computer**;
- **Examples** (`src/examples.js`): the Solder Fume Extractor. More are added as projects get
  drawings.

Opening a link or an example goes to its `?repo=` address, so it can be shared and reloaded. A
GitHub problem says what happened in plain words: not found or private, too many requests this
hour (try again later), no drawings in it.

## 4. Phones and tablets

Under 760 px wide:

- **The header folds:** the app name, the project, Undo and a **Menu** button stay; the other tools
  open from Menu. Find part stays visible.
- **The sheets** stay one scrolling strip, never wrapping.
- **The panel is a bottom sheet** under the drawing: a handle makes it tall or short, and Hide
  panel still hides it.
- **Nothing scrolls sideways.** Pinch, two-finger pan and tapping labels already work (0.5).
- Tested at 375 × 812 with touch.

## 5. Ask with your own Claude key or Ollama

The same way Shape does it, in Easy reading's settings under **AI help (optional)**:

- **Off** (the default), **Claude (your API key)** or **On this computer (Ollama)**.
- The key stays in this browser: in memory, or in its storage when **Remember** is ticked. It is
  never put in a progress file, a board file or a link. Using it is billed to the owner's account.
- **Test it** asks for a one-line hello.
- The part card's Ask box gets **Ask here**: the same context "Copy for Claude" builds goes to
  Claude or Ollama, and the answer shows as plain text in the card.
- **Rules (CSP):** `connect-src` adds `https://api.anthropic.com`, `http://localhost:11434` and
  `http://127.0.0.1:11434`.
- Tests never reach Claude, Ollama or GitHub: the browser tests answer for them.

## 6. Order

Sources and links, then the start screen and examples, then phones, then AI help. Tests first; push
as each lands.
