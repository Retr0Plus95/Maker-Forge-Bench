# Bench 1.0.5 "The case": case parts to print, and What you have

The order agreed on 2026-11-20 (roadmap, "In batches"): after 1.0.4, **1.0.5 case parts (STL/3MF, reusing Shape's
readers) with a "What you have" card**. The owner's words when it was asked for (2026-11-27, in Maker Forge's session):
the improvements and bug finding go to Bench as well. The calls marked *(my call)* are mine. The owner reads this and
reviews the branch.

## 1. Why

The four-channel bench supply (`Retr0Plus95/four-channel-psu`) is designed and not built yet. Its case is nine STL files
made with Maker Forge (`case/stl/`), and `case/README.md` has a table saying what each one is and how to print it
(PETG, upright, supports on…). Today Bench doesn't even list STL files. The board, the wiring and the case are one
build, but Bench shows only the first two, and nothing says how far the whole build has got.

1.0.5 makes Bench read the project's case parts and show them as things to print and tick. A card at the top of the
Guide tab says how far each part of the build has got.

## 2. Goals

1. **Case parts.** Every STL and 3MF in the project is a part to print, listed in the **Case** tab with:
   - its size;
   - about how much plastic it takes (grams and metres of filament);
   - whether it fits your printer;
   - a small picture;
   - what the README says it is and how to print it.
2. **Your printer.** Pick it from a short list or type your bed's size. A part too big as it lies says so, and says
   whether it would fit laid on another side.
3. **A tick per part:** Printed, one undo step, kept with your progress.
4. **Look in 3D.** The part on your bed inside the build volume: green when it fits, red when it doesn't.
5. **What's wrong** in plain words:
   - a file that isn't a model;
   - a file too big to read;
   - a part that's tiny (the wrong units?);
   - a surface turned inside out;
   - a surface with gaps.
6. **What you have.** One card at the top of the Guide tab: parts soldered, build steps, README steps, wiring, checks
   and case parts printed, each with its count and a button to its tab, then "Left to do".

## 3. Non-goals and anti-goals

- **Not a slicer:** no G-code, and no exact weights. The weight is an estimate and says so.
- **No editing parts:** the model doctor in Maker Forge Shape fixes broken files. Bench names it.
- **No count of copies:** "print four plates" in prose isn't read. Each file is one part. *(my call: the README's
  wording varies too much to read safely; a "how many" column in the table can come later.)*
- **No colours from a 3MF:** a painted 3MF is drawn in one colour.
- **Anti-goal: an alarming warning on a good file.** An edge where two solid pieces meet isn't a gap; only true gaps
  are named, and as information, not a warning.
- **Anti-goal: blocking.** A part too big is flagged; nothing is locked.

## 4. Constraints (standing)

- Works on the website alone: GitHub link and picked folder as well as dev.py.
- `deploy/csp.txt` unchanged. A 3MF is a zip, and the browser's own `DecompressionStream('deflate-raw')` opens it,
  so there's no new library.
- Pages built with `el()`, never innerHTML.
- Every change goes through `history.do`.
- Storage keys are `bench.*`.

## 5. Approaches

- **A. Read the parts in Bench (chosen).** The readers follow Shape's (`parseSTL`, `parse3MFModel` in Maker Forge's
  `src/core.js`), so a file reads the same in both apps. Facts come from the triangles: size, volume, area, gaps.
- **B. Ask Shape to send its parts list.** Only works for projects made in Shape and opened on the website. The
  STLs in a repo are what every builder has.
- **C. A `case` list in forge-project.json.** It would duplicate what the README already says. It could come later
  for projects without a README table.

## 6. Design

### 6.1 Which files

Every `.stl` and `.3mf` in the project (any folder), listed by dev.py, from GitHub and from a picked folder like the
other project files. A part bigger than 64 MB, or with more than four million triangles, isn't read, and says so.

### 6.2 Reading (`src/caseparts.js`, no page code, unit-tested)

**The readers:**
- `parseSTL`: binary or text.
- `zipEntries` / `zipRead` / `unzip3MF` read the 3MF's zip directory.
- `parse3MF` handles build items, components with transforms, `p:path` objects in other model files, and the model's
  unit (inches and metres become mm).

**The facts:** `meshFacts` gives the triangles, size, volume, area, the edges on a gap, and whether the surface is
inside out.

**The plastic** (`plastic`) assumes 1.2 mm of solid wall under every surface and 15 % infill inside, for 1.75 mm
filament. The densities are PLA 1.24, PETG 1.27, ABS 1.04, ASA 1.07, TPU 1.21, PC 1.20 and Nylon 1.14 g/cm³.

**The printers:**

| Printer | Bed (mm) |
|---|---|
| Bambu Lab X1, P1 or A1 | 256 × 256 × 256 |
| Bambu Lab A1 mini | 180³ |
| Prusa MK4 | 250 × 210 × 220 |
| Prusa Core One | 250 × 220 × 270 |
| Prusa MINI | 180³ |
| Creality Ender-3 or K1 | 220 × 220 × 250 |
| My own size | 20–2000 mm each way |

`fitOnBed` tries the part as it lies, turned 90° on the bed, then on its other sides.

### 6.3 What the README says (`partNotes`)

Every README.md in the project, up to 20 and 256 KB each, is read. A table counts when its header has:
- a **File** (or Part, STL) column;
- and a **What** (description) or **Print** (settings, material) column.

The File cell is read like this:
- Its code spans, links and words ending in .stl or .3mf name files, from the README's folder.
- A `*` in a name matches any characters (`stl/*-lenses-2.stl`).
- A Print cell that says "same" (or "as above", "ditto") takes the row above's.

The plastic named in the Print words (PETG, PLA…) is that part's plastic. The rest take the one you pick.

### 6.4 The Case tab

- The tab shows only when there are parts. It holds "Case parts to print", a progress bar and the total
  ("9 parts, about 1 kg of PETG (342 m of 1.75 mm filament)"), followed by:
  - **Printer**, with your own size in three boxes;
  - **Plastic**, for parts the README doesn't name;
  - "N parts are too big";
  - **Only not printed**;
  - **Copy as text**.
- Each part, in the README's order and then by name, shows:
  - its picture (click: Look in 3D) and the Printed tick;
  - its name and folder;
  - size · grams of plastic · metres;
  - What it is, and Print;
  - "Fits your printer", or the warnings;
  - Look in 3D and Open the file.
- **Look in 3D** is a dialog. The part sits on a 10 mm grid the size of your bed, inside the build volume's edges
  (green or red).
  - It offers 3/4, Top, Front and Close up.
  - You drag to turn it and scroll or pinch to zoom.
  - three.js loads only when the first part is read.

### 6.5 What you have

At the top of the Guide tab, a row for each piece the project has, each a button to its tab:
- Parts: soldered;
- Build steps;
- README steps;
- Wiring;
- Checks;
- Case: printed, with the plastic in all.

Then come "Left to do: 4 parts to solder · 3 README steps · 7 case parts to print" and "Also in the project:
5 drawings, 2 PDF datasheets".

It shows only when there's more than one thing to track and one of them is the case, the README or the wiring. A
board-only project looks as before. *(my call)*

### 6.6 Ticks, Undo, progress

- Printed ticks live in `drawing.printed`: project paths to STL or 3MF files. `cleanDrawingProgress` keeps at most 500
  and drops anything else.
- So saving, versions, the progress file and Undo need no new code.
- Start over clears them with the other ticks.
- Your printer (`bench.printer`) and plastic (`bench.caseMaterial`) are kept per browser, not per project: they're
  yours, not the project's.

## 7. Left to the builder

Exact CSS, the colours per plastic in 3D, the camera's framing, and the picture size.

## 8. As built

- `src/caseparts.js`:
  - the readers: `parseSTL`, `zipEntries`, `zipRead`, `browserInflate`, `unzip3MF`, `parse3MF`, `readPart`;
  - the facts and the printer: `meshFacts`, `plastic`, `fitOnBed`, `PRINTERS`, `cleanPrinter`, `MATERIALS`,
    `cleanMaterial`;
  - the README and the words: `printHint`, `partNotes`, `partWarnings`, `sizeText`, `gramsText`, `metresText`;
  - the limits: `PRINTED_PATH`, `MAX_PART`, `MAX_TRIS`.
- `src/case-panel.js`: `renderCase`, `caseText`, `renderHave`.
- `src/case3d.js`: `partThumbnail` (one renderer for every picture) and `createCaseView`.
- `src/app.js`:
  - `loadCaseParts` reads only parts that are new or changed (by path and mtime). It keeps up to three million
    triangles in memory and reads a part again to look at it when it's been let go.
  - Also `caseView`, `renderCasePanel`, `togglePrinted`, `showCasePart` and `renderHavePanel`.
- **What you have redraws only when its words change.** The panel's MutationObserver redraws the tabs on every change,
  and the tabs draw this card, so drawing it unconditionally looped forever. It was found in the first browser run.
- **On the real bench supply** (nine STLs, `case/README.md`):
  - Every part is read, with its README words. The lids share one row; the lenses match through `*`; the plates say
    "same".
  - The total comes to about 1 kg of PETG. Every part fits a 256 mm bed.
  - The first version counted every edge not shared by two triangles as a gap. It said the left half had 2404. Those
    are edges where two solid pieces meet, used by four triangles each. Only edges used an odd number of times count
    now, and the bench supply has none.
- **Found and fixed on the way:** Ctrl+Z, Ctrl+Y and Ctrl+S did nothing while a tick box had the focus, which it keeps
  after you click it. Bench treated every input as typing. Now only text boxes count as typing; tick boxes and buttons
  don't.
- **Tests:**
  - `tests/unit/caseparts.test.js` (10);
  - progress, file-list and tab tests;
  - `tests/browser/case.test.js` (9) on `tests/fixtures/case-like`. That fixture is written like the bench supply's
    case folder, with a part too long, a text STL, a 3MF with components, a broken file and an open surface.
