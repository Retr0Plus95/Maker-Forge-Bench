# Bench 1.0.3 "Wires from the drawing": design

Status: **approved by the owner from the sketch shown in the session ("looks ok go ahead", 2026-11-20)**.
The calls marked *(my call)* are mine; the owner reads this and reviews the branch before they choose the
merge. Built on `release-1.0.3`.

## 1. Why

The owner finished the fume extractor and moved on to a bench power supply: a ready-made kit board,
already soldered, plus about twenty wires to a transformer, a fuse, a switch, a meter, two knobs, two
binding posts and a fan. What they needed was help with the wiring. Their wiring drawing (made in a
Claude chat with a plotting tool) has every wire numbered W1–W20, a wire table, notes and the power-up
checks. Opened in Bench (2026-11-17), it gave nothing: 9 sheet tabs, no parts, no checks, "its text is
drawn as shapes".

The owner wants **Bench alone** to handle pictures and blueprints of all kinds, say when something is
wrong or missing in them, ask the user for what it needs to make the steps, and show what the user needs.
**Claude only as a last resort.** No change to the website's security rules (`deploy/csp.txt`).

This release is part 1 of 3 (agreed order):
1. **Read the drawing and say what's missing** (this release).
2. Teach Bench from a picture: photos and scans it can't read (tap and name, type or paste the wires,
   one question at a time).
3. PDFs: show them and read their text (already in the roadmap's 1.2), only with a PDF reader that fits
   the security rules.

## 2. Approaches (picked: A)

- **A. Read exactly, ask for the rest (picked).** Bench reads every piece of real text a drawing holds,
  and where it sits; rebuilds parts, wires and checks from it; flags what's wrong or missing; asks the
  user one question at a time for what it can't work out. No AI, no rule change.
- B. A plus reading printed letters in photos (OCR). Needs WebAssembly, so a change to the security
  rules, and a large first download; still can't follow wires in a photo. Later, if photos of printed
  manuals turn out common.
- Rejected earlier: Bench asking Claude or Ollama to read every picture (the owner wants Claude as a
  last resort only).

## 3. Found while looking

- The owner's drawing draws its letters as shapes, but the plotting tool (matplotlib) writes each
  label's text as a comment just before its letter shapes: `<!-- W9 -->` then
  `<g transform="translate(882.47 279.90) scale(0.056 -0.056)">` with one `<use>` per letter. All 347
  labels are there, with their place. Bench's cleaner keeps comments, so Bench can read them exactly.
- In that drawing the wire table has a header row (W, FROM, TO, WIRE, NOTE, AT), one row per wire,
  cells left-aligned under their header; the power-up checks are a titled list ("POWER-UP CHECKS · in
  this order") of a short key (OFF, TP1, LIMIT) and a sentence; the notes are a titled list ("NOTES") of
  a number and lines of text. The wire tags (W1–W20) and the test points (TP1–TP4) also sit on the
  drawing itself.

## 4. What the builder gets

### 4.1 Drawings Bench couldn't read before
Labels written as comments before their letter shapes count as text everywhere: Find part finds them and
rings them, and parts are guessed from them, like KiCad's invisible labels.

### 4.2 Wires (Wiring tab, first section)
When a drawing has a wire table, the Wiring tab opens with **Wires**, read from that drawing:

```
Wires (read from wiring-blueprint)               3 of 20 done
Bench needs 1 thing:
  Note 4 asks "Which AC24V screws?" before W7 and W8.   [Answer] [Not needed]

  230 V: unplug before touching
  ☑ W1  X1 wire A → F1 in (coil contact)   mains 0.75 mm²   through the clamp
  ...
  ☐ W9  U1 OUT + → J1 + red post            0.5 mm² red      up to 0.7 A
  ☐ W13 PM1 thin black → U1 OUT −           meter lead       NOT GND: note 1
```

- One row per wire, in the table's order: number, from → to, the wire, the note. A tick box each; each
  tick is a change you can undo, named in the build log ("Wired W9").
- Wires whose wire or note says mains or 230 V are listed first under **230 V: unplug before touching**
  *(my call: the table's own order within each group)*.
- A wire whose note says "note N" shows that note's text under it.
- **Show** rings the wire's tag(s) on the drawing and the labels of the parts at both ends, and opens the
  sheet if another one is showing.
- **Only not done** and **Copy** as in What to wire. The tab's count includes the wires.
- At the end: "Then the checks" opens the Checks tab.

### 4.3 What Bench needs (top of Wires)
Each item says what's wrong or missing, and what to do. Items:
- a wire with no "from" or no "to";
- a wire number in the table twice;
- a part named in the table that's drawn nowhere else on the drawing;
- a wire in the table with no tag on the drawing, and a tag on the drawing with no wire in the table;
- a note that asks a question ("Which AC24V screws?") and that a wire points to: answer it before those
  wires (the answer is kept and shown with the wires);
- a test point on the drawing with no check, and a measuring check with no expected reading;
- a drawing with readable text but no wire table, when there's no project file: "Bench found the parts
  but not which wires go where; it needs a table with From and To columns";
- a drawing whose text is drawn as shapes with nothing to read.

Answering (typed text) or **Not needed** is a change you can undo. The answers are kept with the progress.
Items about the drawing itself (a missing tag, a repeated number) have only **Not needed**: they're fixed
in the drawing, and the item goes when the drawing is fixed.

**Last resort:** under an unreadable drawing, **Ask Claude** copies a question asking for the same drawing
as an SVG that keeps its text as real text, with a wire table (W, From, To, Wire, Note), and opens
claude.ai, where you attach the picture. Saved into the folder, Bench reads that.

### 4.4 Checks from the drawing (Checks tab)
The drawing's checks list joins Checks, in its order, each a tick box: "OFF · Unplugged, meter on beep:
… silent", "TP1 · C1 big cap: 24–27 V with no load". **Show** on a TP check rings that test point on the
drawing. Ticks are kept like the other checks.

### 4.5 Steps
The steps for a wiring job are the wire list in order, then the checks in order *(my call: no Guide
steps are made; the Guide stays the soldering steps from a project file)*.

## 5. How the reading works (for the builder)

- **Text with a place:** every `<text>` (its x/y and its ancestors' transforms), and every comment
  followed by a group whose children are `<use>` or `<path>` letters (the group's transform). Position in
  the sheet's own units; size from the font size or the group's scale (matplotlib: scale × 100 pt).
- **Rows:** texts whose baselines are within half a text height.
- **Wire table:** a row with a "from" header (from, från) and a "to" header (to, till); optional number
  (w, no, nr, #, wire no), wire (wire, cable, size, kabel), note (note, notes, anm). Rows under it, while
  rows keep coming at about the same spacing, and a cell belongs to the header column it starts under.
- **Ends:** "U1 OUT +" is part U1, end "OUT +"; a cell can name several ends separated by commas
  ("M1 red, LED1 +"). A first word is a part when it looks like a part name (R6, TB1, LED1, PM1).
- **Checks list:** a title with the word check(s); rows under it of a short key and the rest.
- **Notes list:** a title "notes"; a number on its own starts a note, the lines to its right belong to it.
- **Expected readings:** "24–27 V", "≈ 20 V", "12.0 V", "0 → ≈ 20 V" are read as volts.
- **Guessed parts** leave out the wire tags and the test points once a table or checks list names them.
- Only drawings without a project file's board get the "no wire table" item; projects with a board keep
  What to wire from their connections, and nothing changes for them.

## 6. Not in this release
- Photos and scans (part 2), PDFs (part 3).
- Following drawn lines between parts when there's no table.
- Feeding the drawing's readings into Find a fault (it needs the project's connections).

## 7. Where this differs from the sketch shown
- The sketch's question ("W7 and W8 … only 2 of its 3 screws are inputs. Which two?") comes from note 4
  itself, which asks "Which AC24V screws?": Bench asks a note's question, it doesn't reason about
  terminals.
- The sketch said the readings feed Find a fault: not in this release (§6).

## 8. As built

- `src/drawing.js`: `sheetTexts` (every label with its place and size: `<text>`, and a comment followed
  by its letter group), `rowsOf`, `readWireTable`, `endsOf`, `readChecks`, `readNotes`, `questionOf`,
  `expectedVolts`, `readDrawing`, `drawingNeeds`, `wiresText`, `cleanDrawingProgress`, `notAPart`. At most
  20 000 labels a sheet, 500 characters each.
- Find and the part guesses read the same labels (`search.js` uses `sheetTexts`), so the PSU drawing's
  labels are found by Find. The fume extractor's five drawings still give 445 labels, and read no wire
  table, checks or notes: nothing changes for a project with a board (a unit test pins this).
- On the real bench PSU drawing (`wiring-blueprint.svg`): 347 labels, 20 wires (W1–W5 under Mains),
  7 checks (two named OFF, both listed, in the drawing's order), 7 notes, and one need: note 4's
  "Which AC24V screws?" before W7 and W8.
- The Wiring tab's new first section `#wires` (`renderWires` in panel.js); the drawing's checks at the
  top of the Checks tab (`renderChecks`'s `drawingChecks`), counted in the tab's number with ids like
  `dcheck:wiring-blueprint:2`. The Wiring tab's number counts the drawing's wires too.
- Progress keeps `drawing: { done, answers, dismissed }`: saved, in versions, in the progress file and
  under Undo. Each change is a history step ("Wired W9", "Answered: …", "Not needed: …"); "Wired W9"
  shows the toast "W9 wired" with the buzz. Start over clears the wires done and keeps your answers.
- Show rings the wire's tag and the labels of the parts at its ends (or a test point's labels), opens
  that drawing if another is showing, and zooms so all of them fit. When they're far apart (W9 on the
  PSU drawing: its tag, U1 and J1) that is close to the whole sheet, and the rings are small.
- Ask Claude (last resort) shows only for a drawing whose text is all shapes; it copies a request for
  the same drawing as an SVG with real text, a W/From/To/Wire/Note table, and Checks and Notes lists,
  and opens claude.ai.
- Found in self-review: a drawing changed on disk in a folder with a project file wasn't read again
  for its wires (only folders without one were). Live reload re-reads every drawing now.
- Tests: `tests/unit/drawing.test.js` (20), a progress-file test in `checklist.test.js`, the tabs test;
  `tests/browser/drawing.test.js` (10) on `tests/fixtures/psu-like/wiring.svg`, a small drawing laid out
  the way matplotlib saves one, with things wrong on purpose (made by a script, not kept in the repo).
