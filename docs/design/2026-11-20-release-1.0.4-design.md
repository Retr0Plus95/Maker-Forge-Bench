# Bench 1.0.4 "How to build it": the project's README as a guide, with mains safety

Owner's words (2026-11-20): "for this project the pcb is already done and soldered. maybe adding a wiring
reference part to bench? like how to connect to the transformer mains and maybe adding safety tips and
instructions with pictures and yes write the design and start working".

## 1. Why

The bench PSU's board is soldered. What's left is the wiring (mains, transformer, meter, pots, fan), the
case and the first power-up. Bench 1.0.3 already lists the drawing's 20 wires, mains first. But the
*how* lives in the project's README: the steps, the meter trap, the fuse holder, setting the buck to 12 V
before anything is connected, the first power-up, the safety section. Today Bench doesn't read the README,
so you read it in another window and tick wires in Bench.

1.0.4 makes Bench read the README itself and show it as steps to tick, each with a picture of its wires
cut from the drawing, and puts a mains safety list in front of the mains work. As before: Bench works from
the files you have, says what's wrong or missing, and Claude is not involved.

## 2. Goals

1. **README steps.** Bench finds the project's README.md and shows its wiring, assembly and first power-up
   sections as numbered steps you tick, in the README's order, with its words, bold, notes and pictures.
2. **The wires of each step.** A step lists the drawing's wires it's about: those it names (W1, W2…), and,
   in a wiring section, the wires whose ends match the words it puts in bold (AC24V, thick black, OUT −).
   Each wire ticks the same as in the Wires list.
3. **A picture for each step.** A step with wires shows the drawing cropped to those wires. Clicking the
   picture opens the drawing in the big view with all of the step's wires ringed. Pictures the README puts
   in a step show there too.
4. **Mains safety.** When the drawing has mains wires or the README talks about mains, a short safety list
   comes first, to tick before the mains work. Steps with mains wires say so in red while it isn't all
   ticked. The README's own Safety section shows under it, and its Troubleshooting table at the end.
5. **What's wrong or missing,** in plain words: a step names a wire that isn't on the drawing; a picture
   the README shows isn't in the folder; wires on the drawing that no step mentions.

## 3. Non-goals and anti-goals

- Not in 1.0.4: case parts (STL/3MF) and the "What you have" card move to **1.0.5**; wires drawn on the 3D
  board and the whole assembly later (the order agreed on 2026-11-20 stays, one release on).
- Bench doesn't write instructions of its own beyond the fixed safety list. It never invents steps.
- No HTML from the README is used: tags show as text. No pictures from the internet (the security rules
  don't allow them): a web picture shows as its link text.
- Anti-goal: blocking the user. The safety list warns; it never locks a step.
- Anti-goal: guessing wrong. A bold word matches a wire only on whole words; when nothing matches, the step
  simply has no wires listed, and the wires left over are named.

## 4. Constraints (standing)

Works on the website alone (GitHub link and picked folder as well as dev.py). `deploy/csp.txt` unchanged.
Pages built with `el()`, never innerHTML. Every change through `history.do`. Storage keys `bench.*`.
Claude only as a last resort (not used here).

## 5. Approaches

- **A. Read the README (chosen).** The author already wrote the how: the steps, the traps, the order.
  Bench shows it as steps and ties each step to the drawing's wires. Works for any project with a README;
  without one, nothing changes (the Wires list and the safety list still show).
- **B. Bench makes steps from the drawing alone** (group the wires by part: mains, transformer, meter…).
  Loses everything the author explained (the meter trap, set the buck first), so it's a poorer guide;
  the Wires list already does the grouping that matters (mains first).
- **C. Ask Claude to write a guide.** Against the owner's "Claude only as a last resort".

## 6. Design

### 6.1 Which file

`README.md` (any case) at the top of the project; if there's none at the top, the one in the shallowest
folder. At most 256 KB: a bigger one isn't read, and the status line says so. dev.py lists README.md files
(not other .md files); GitHub and the folder picker keep them too. Live reload re-reads it when it changes.

### 6.2 Reading it (`src/readme.js`, no page code, unit-tested)

A small Markdown reader: headings, paragraphs, numbered and bulleted lists (with nested lists and
paragraphs inside an item), tables, quotes, rules; inside a line: **bold**, *italic*, `code`, links
(text only) and pictures. Raw HTML stays text. At most 5 000 blocks.

Sections are picked by their heading (level 2 or 3), in the README's order:

| Heading looks like | Shown as |
|---|---|
| wiring, wires | steps (and bold words find wires) |
| assembly, putting it together, build order | steps |
| first power-up, power-up, power on, testing | steps |
| safety, warning | a card to read, under Bench's safety list |
| troubleshooting | a card to read, at the end |

A steps section shows its top-level numbered list as steps; what comes before and after it (a note in a
quote, say) shows as text around them. A steps section with no numbered list shows as a card to read.
Every other section is left out. A step's id is `readme:<section slug>:<n>`.

### 6.3 The wires of a step

- Named: every `W` and a number in the step's text that is a wire on a drawing (any section).
- Matched (wiring sections only, when the step names none): each bold phrase of 3 or more characters with
  a letter, and a bold 1–2 character word together with the word before it ("header **U**" → "header U"),
  matched on whole words against each wire's From and To, case and minus signs (− –) ignored.
  On the bench PSU: step 2 "AC24V" finds W7 and W8; step 4 "thick black", "OUT −", "thin black",
  "thick red", "thin red" find W11–W14; step 5 "header U", "header A" find W19 and W20.
- A step's wire shows as a small row: tick, `W7`, from → to, and "(by AC24V)" when matched rather than
  named. Its tick is the Wires list's tick.

### 6.4 Pictures

- A step with wires on a drawing shows that drawing cropped to the labels of its wires and their ends
  (padded, at least a fiftieth of the sheet, wider than high), as an `<img>` of the drawing's own file with
  `#svgView(viewBox(…))`: no copy of the drawing, and it works from dev.py, GitHub and a picked folder
  (checked in Chromium on 2026-11-20). Clicking it opens the drawing in the big view with every wire of
  the step ringed, zoomed so they all fit; clicking again hides the rings (like Show).
- A README picture (`![…](images/x.png)`) in a step or a card shows from the project; a missing one says
  "picture images/x.png isn't in the folder".

### 6.5 Mains safety

Shown at the top of the guide when a drawing has a mains wire (1.0.3's Mains group) or the README's text
mentions mains or 110–240 V. Bench's own list, fixed text, each to tick:

1. Unplugged: the plug is out of the wall, not just switched off.
2. Fuse first: the fuse sits in the mains wire before the switch.
3. Every mains joint covered: heat-shrink over it, no bare copper showing.
4. Mains kept apart: tied down, away from the low-voltage wires and the board.
5. Cable held: clamped where it comes in, so a pull can't reach the joints.
6. Metal you can touch goes to the plug's earth pin. (A plastic case with a double-insulated transformer
   needs no earth.)
7. Before you plug in, with the plug out and the meter on beep: the mains pins to anything low-voltage are
   silent.

Under it, in plain text: "Mains can kill. If you're not sure about any of these, have someone who knows
mains wiring check it before you plug it in." While the list isn't all ticked, a step with a mains wire
shows "Mains: tick the safety list first" in red. Nothing is locked.

### 6.6 Ticks, Undo, progress

Ticking a step or a safety line is a history step ("Done: Wiring step 3", "Safety: Unplugged") with a toast
("Step 3 done"). Progress keeps them with the drawing's: `drawing.steps` and `drawing.safety` (lists of
ids), so they are saved, kept in versions and the progress file, and undone like the rest. Start over
clears the steps and the safety ticks along with the wires done; your answers stay. The Guide tab's number
counts the README steps and safety lines with the build steps.

### 6.7 Where it shows

A new first section in the Guide tab, `#readme`, headed "How to build it (README)". The build steps
(`#steps`) follow. With no README and no mains, the section is hidden. "Only not done" hides steps done.

### 6.8 What's wrong or missing

At the top of the section, as a short list, each with Not needed (kept in `drawing.dismissed`):
- "Step 3 of Wiring names W21, which isn't on the drawing."
- "The README shows images/x.png, which isn't in the folder."
- "No step mentions W6, W15, W16, W17, W18. They're in the Wiring tab."
