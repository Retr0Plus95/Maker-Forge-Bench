# Release 0.4 "Your board" — plan

Design: `docs/design/2026-11-13-your-board-design.md`. Branch `release-0.4` from main (0.3 merged).

**For every task:**
- Write the failing tests first (unit tests for pure modules, browser tests for the page).
- Implement, then run `bash check.sh`; it must end ALL CHECKS PASSED.
- Commit and push.

**Global constraints:**
- No `innerHTML`; project and progress data are untrusted and get checked on read.
- Everything you change can be undone with Ctrl+Z and is saved.
- New progress fields are optional, so 0.3 progress files still open.
- The CSP stays as it is.

## Task 1: What to wire (F1, improvements 2–5)

- **`src/wiring.js` (pure):**
  - `wiringGroups(board, describe)` gives the nets with two or more members, power first, each
    member as `{ key: 'REF:PIN', ref, pin, text }`.
  - `isPowerLabel`, `isGroundLabel`.
  - `wiringText(groups, wired)` for "Copy as text".
  - `stillToWire(connections, wired)` for the card.
- **`checklist.js`:** export and import an optional `wired` list (each key `REF:PIN`, 200 characters at
  most).
- **The page:**
  - a `#wiring` section with groups as `<details>`, the "Only not wired" switch, "Copy as text"
    and each group's "Show";
  - card connection lines get a wired tick and "Still to wire".
- **Tests:**
  - unit: groups for the fume project (+12 V first, then +5 V, 0 V; U2 pins 7 and 20 on +5 V);
    text; import of `wired`.
  - browser: tick U2 pin 7 in the list, the card shows it, Ctrl+Z undoes, it survives a reload;
    "Show" rings the parts.

## Task 2: chip pin view (F2)

- **`src/pinout.js` (pure):** `pinLayout(part, side)` gives each pin's `{ pin, x, y, labelSide }` for
  a DIP (counter-clockwise from the top, the rows 3 holes apart, as in the board data) or a
  header; underneath is mirrored.
- **The card:**
  - "Show pins" draws the SVG with a pin's number, line label, colour class and wired dot;
  - the Top / Underneath switch is remembered (`bench.pinSide`);
  - clicking a pin shows its connections.
- **Tests:**
  - unit: U2 seen from the top has pin 1 top left, 14 bottom left, 15 bottom right and 28 top
    right; underneath swaps sides; a header is one row.
  - browser: U2's pins drawn, pin 7 says +5 V, Underneath puts pin 1 on the right.

## Task 3: your board from photos (F3, improvement 28)

- **`src/myboard.js` (pure):**
  - `anchorFor(board)` and `anchorPins(board, ref)`, which give the pins A and B to tap;
  - `photoTransform(fA, fB, pA, pB, side)` gives `{ toPixel(f), toBoard(p) }`;
  - `snap`;
  - `cleanMyBoard(raw, isRef)` for stored and imported data.
- **The viewer:**
  - `setOverlay(svg | null)` for image sheets;
  - `onPointClick(fn)`, which reports a tap in image pixels;
  - `imageSize()`.
- **The page:**
  - "My board" on image sheets, and the `#myboard` panel section (side, line up, status);
  - card "Place on my board" / "Show on photo";
  - an overlay of the anchor's pins and placed parts;
  - "Brighter".
- **`checklist.js`:** an optional `myBoard` in progress files.
- **Tests:**
  - unit: transform round trips, mirror underneath, snap, hostile data dropped.
  - browser: on a PNG fixture, tap two points; the overlay draws 28 pins at the right pixels;
    place R8 by two taps; undo; reload keeps it.
