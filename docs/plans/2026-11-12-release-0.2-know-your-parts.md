# Maker Forge Bench 0.2 "Know your parts" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bench reads a project's `forge-project.json` and knows its parts. Clicking a part shows
what it is, why it's there, which way round it goes, and its datasheet. There's a build checklist
that ticks parts green on every sheet, Ask Claude, two sheets side by side, and Maker Forge's look
with Easy reading. Every change can be undone, and progress saves itself.

**Architecture:** This builds on 0.1's modules. The new logic has no page code and is unit-tested
in Node: `project.js` (reading the project file), `history.js` (undo/redo), `store.js` (saved data),
`checklist.js` (progress files and change notes) and `ask.js` (the context text). The page code
(`app.js`, `viewer.js`, the new `panel.js` and `settings.js`) is tested in Edge or Chrome through
Playwright.

**Tech Stack:** As in 0.1: HTML, CSS and JavaScript ES modules; Python 3.10+ standard library;
Node 24 `node --test`; dev-only `@xmldom/xmldom` and `playwright`.

**Spec:**
- `docs/design/2026-11-12-maker-forge-bench-design.md`: §6 (the project file), §7.4 (part card),
  §7.5 (the same part on every sheet), §7.7 (build checklist), §7.8 (Ask Claude), §7.10.
- `docs/design/2026-11-12-board-view-parts-ui-design.md`: §5 (datasheet button), §6a (undo,
  autosave, save as file), §7 (UI family) and §10 (what 0.2 contains).

**Repo:** `G:\Bench-Forge`, branch `release-0.2` from `main`. Test project: the fume extractor's
`forge-project.json`, copied to `tests/fixtures/forge-project/fume-extractor.json` from fume repo
commit 5652147.

## Global Constraints

- Everything in 0.1's Global Constraints still holds: no inline scripts, no `innerHTML`, the
  `bench-svg` policy only for `DOMParser`, the 25 MB and 200,000-element limits, plain-words
  messages, LF, the commit trailer, and `bash check.sh` ending `ALL CHECKS PASSED`.
- The CSP gains exactly `font-src 'self'`. `deploy/csp.txt` changes, and nothing else does.
- Saved data lives in `localStorage` under keys starting `bench.`. Nothing else is written.
- **Every change a person makes is undoable:** ticks, flips and settings. Selecting and viewing
  aren't changes.
- Project files and progress files are untrusted. They're parsed as JSON and checked against the
  limits in Task 1 and Task 6, and their text only ever reaches the page through `textContent`.
  A datasheet link must start `https://`. A datasheet file must be a relative path with no `..`,
  `\`, `:` or leading `/`.
- **Colour tokens use Maker Forge's names:** `--bg --panel --panel2 --ink --muted --line --accent
  --accent-ink --accent-soft --stage-top --stage-bot --field --danger --warn --good --r --shadow`.
- **Switches on `<html>`:** `data-theme="dark|light"` (dark by default), `data-contrast="high"`,
  `data-font="clear"`, `data-motion="reduce"`, and the text size as `style.fontSize` (100–175 %).
- **Accent colours:** dark theme `#e0b55a`, light theme `#8a5d0b` (solder gold, readable on each
  background).
- **Selectors the 0.1 tests use keep working:** `#tabs [role=tab]`, `#stage`, `#sheet-host`,
  `#status`, `#sheet-note`, `#find`, `#find-results`, `#flip`, `#flip-banner`, `#live`,
  `#stage-message`.

## Review Focus

1. **A project file listing a sheet whose file isn't in the folder** (the fume extractor lists
   `images/SFE-parts.jpg`): the tab shows, and opening it explains what's missing. Tested in Task 4.
2. **A broken or hostile `forge-project.json`** (truncated, markup in a role, `javascript:` in a
   datasheet link, `../` in a file path): Bench falls back to guessing, and the bad values never
   reach the page. Tested in Tasks 1 and 4.
3. **A progress file from another project, or not a progress file at all:** it's refused in plain
   words and nothing changes. Tested in Task 6.
4. **Undo across different kinds of change** (tick, then flip, then a theme switch): Ctrl+Z steps
   back through them in reverse order. Tested in Tasks 3 and 6.
5. **Two parts whose refs differ only in case, or a guessed part that's really a pin name (`D4`):**
   cards and ticks use the exact ref. Tested in Tasks 1 and 5.

### Task 1: Reading the project file

**Files:**
- Modify: `src/project.js`
- Create: `tests/unit/project-file.test.js`, `tests/fixtures/forge-project/fume-extractor.json`

**Interfaces:**
- Produces:
  - `export class ProjectError extends Error`, with `.code` `'json' | 'format' | 'too-big'`.
  - `export const PROJECT_LIMITS = { maxBytes: 1048576, maxSheets: 200, maxParts: 2000, maxText: 2000 }`
  - `export function parseProject(text: string): Project`, where
    `Project = { name, revision: string | null, repo: string | null, sheets: ProjectSheet[], parts: Part[], extra: object }`.
    - `ProjectSheet = { id, title, file, kind: 'schematic' | 'layout' | 'detail' | 'photo', side: 'component' | 'solder' }`
    - `Part = { ref, value?, type?, package?, role?, polarized: boolean, orientation?, datasheet?, datasheetFile?, note?, qty?, part?, guessed: false }`
  - `export function sheetsForProject(project: Project, files: FileInfo[]): Sheet[]`. A `Sheet` from
    0.1 gains `side` and `missing: boolean`.
  - `export function guessParts(labels: Label[]): Part[]`
- Rules:
  - **Errors:**
    - Text over `maxBytes`: `too-big`, with the message `forge-project.json is bigger than 1 MB, so it wasn't read.`
    - A JSON error: `json`, with the message `forge-project.json couldn't be read (<reason>). Fix the file, or remove it and Bench will guess the parts.`
    - A file where `format` isn't `"forge-project"`, `version` isn't `1`, or `name` isn't a non-empty
      string: `format`, with the message `forge-project.json isn't a Maker Forge project file: it needs "format": "forge-project", "version": 1 and a "name".`
  - **Sheets:**
    - Each needs string `id` and `file`, or it's skipped.
    - `file` must be a safe relative path.
    - `kind` falls back to `schematic`, and `side` to `component`.
    - At most `maxSheets`.
  - **Parts:**
    - `ref` must match `/^[A-Za-z0-9_+.\-]{1,20}$/`. Later duplicates of an exact ref are dropped,
      but `r6` and `R6` count as two different refs.
    - Text fields are cut to `maxText`.
    - `datasheet` is kept only if it starts with `https://`, and `datasheetFile` only if it's a safe
      relative path.
    - `polarized` is `true` only when the value is `true`.
    - `qty` is kept only as an integer from 1 to 100000.
    - At most `maxParts`.
  - **`extra`:** every top-level key except `format version name revision repo sheets parts`, kept
    exactly as it was found.
  - **`sheetsForProject`:**
    - The project's sheets come first, in their order. Each label is `` `${id} ${title}` `` (or just
      the id), the type comes from the file extension (other extensions are skipped), and
      `missing: true` is set when the file isn't in `files`.
    - Then the folder's other drawings follow, using 0.1's `sheetsFromFiles` rules. A file is left
      out when its name without the extension (ignoring case) matches a listed sheet's file name.
  - **`guessParts`:** each distinct label text matching `/^[A-Z]{1,3}[0-9]{1,3}[A-Z]?$/`, in the
    order first seen, becomes `{ ref, polarized: false, guessed: true }`.

### Task 2: Undo history and saved data

**Files:**
- Create: `src/history.js`, `src/store.js`, `tests/unit/history.test.js`, `tests/unit/store.test.js`

**Interfaces:**
- Produces:
  - `export function createHistory(limit = 200)` returns
    `{ do(action), undo(): string | null, redo(): string | null, canUndo(), canRedo(), clear(), subscribe(fn) }`.
    - An `action` is `{ label: string, apply(): void, revert(): void }`.
    - `do` runs `apply`, records the action and clears the redo list.
    - `undo` and `redo` return the action's label, or `null` when there's nothing to do.
    - `subscribe(fn)` calls `fn({ canUndo, canRedo, undoLabel, redoLabel })` after every change.
  - `export function createStore(storage, prefix = 'bench.')` returns
    `{ get(key, fallback), set(key, value): boolean, remove(key), keys(): string[] }`.
    - Values are stored as JSON.
    - A value that can't be read gives `fallback`.
    - `set` returns `false` when storage refuses (quota).
    - `keys()` lists only keys under the prefix, with the prefix removed.
  - `export function projectKey(project, root): string` gives
    `` `progress:${project ? project.name : root}:${project && project.revision ? project.revision : ''}` ``.

    - **Save progress as file** downloads `<name>-progress.json`.
    - **Open progress file** (file input, `.json`) imports it as one undoable action. A file
