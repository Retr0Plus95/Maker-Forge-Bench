# Bench 1.0.5 "The case" Implementation Plan

> Native execution: implemented in this session, test first where the reader is concerned, one self-review of the
> branch at the end.

**Goal:** Bench lists the project's STL and 3MF files as case parts to print, each with:
- its size;
- the plastic it takes;
- whether it fits your printer;
- what the README says;
- a Printed tick and a look in 3D.

It also gets a "What you have" card for the whole build.

**Architecture:**
- `src/caseparts.js` (no page code) reads the files and works out the facts.
- `src/case-panel.js` draws the Case tab and the card with `el()`.
- `src/case3d.js` draws the pictures and the 3D dialog with three.js r128.
- `src/app.js` reads the parts from the source. It keeps ticks in `state.drawing.printed` and the printer in
  `bench.printer`.

**Spec:** `docs/design/2026-11-27-release-1.0.5-design.md`

## Global constraints

- `deploy/csp.txt` stays unchanged:
  - no innerHTML;
  - no new library (the 3MF zip opens with `DecompressionStream`);
  - every change goes through `history.do`;
  - storage keys are `bench.*`.
- Works from dev.py, a GitHub link and a picked folder.
- A part is at most 64 MB and four million triangles.

## Review focus

1. A broken or hostile file (not a model, a zip bomb, a 3MF whose components loop) says so and never hangs the page.
2. README words are always text.
3. A project with no parts looks exactly as before: no Case tab, and no What you have card unless the README or wires
   make two things to track.
4. Live reload: a part changed on disk is read again; a new one is added.
5. Undo, Start over, the progress file and versions keep the Printed ticks.

## Tasks

1. `src/caseparts.js` and `tests/unit/caseparts.test.js`: the readers, facts, printers, plastic, fit, README tables
   and warnings.
2. The file lists:
   - `sources.js`'s `PROJECT_EXT` and dev.py's `PROJECT_TYPES` take `.stl` and `.3mf`;
   - unit and Python tests;
   - `.gitattributes` marks them binary.
3. Progress: `drawing.printed` in `cleanDrawingProgress`, and Start over clears it.
4. The Case tab in `paneltabs.js`, `index.html` and the style. Then `case-panel.js`, `case3d.js`, and the app wiring
   with the dialog.
5. What you have: `renderHave`, drawn from `renderPanelTabs` only when its words change.
6. `tests/browser/case.test.js` and `tests/fixtures/case-like`.
7. Docs:
   - README (features, status);
   - ROADMAP (1.0.5 done, what's next);
   - the What's new line;
   - `APP_VERSION`;
   - the design's As built section.
