# Release 0.9 "Real parts" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real 3D parts from KiCad's library in Bench, KiCad projects opened directly with their
checks, and a better 3D view.

**Architecture:** A Python converter turns about 150 KiCad `.wrl` models into GLB files plus one
`index.json` (the Maker Forge Library, under `src/library/`). Pure modules match a Bench part to
a model and place it; `board3d.js` swaps the models in over its own simple ones. KiCad projects
are read in the browser by a small bracketed-text reader. With `dev.py` and KiCad installed,
`kicadcli.py` runs `kicad-cli` into a cache outside the project, for sheets, the exact 3D board,
ERC/DRC and factory files.

**Tech Stack:** Python 3 standard library (converter, `dev.py`); ES modules in the browser under
a strict CSP; three.js r128 with its GLTFLoader and GLTFExporter (0.128.0); `node --test`;
Playwright on Edge.

**Spec:** `docs/design/2026-11-14-release-0.9-design.md`. Branch `release-0.9`, worktree
`G:\Bench-Forge-0.8`.

## Global Constraints

- The CSP in `deploy/csp.txt` stays exactly as it is. Pages are built with `el()`/`createElement`
  only, under Trusted Types; no `innerHTML`, no `eval`.
- Every change a user makes can be undone (`history.do`) and is saved. New progress fields are
  optional, so 0.8 progress files still open.
- three.js stays r128 (`src/three.module.js`). The two vendored files import
  `'./three.module.js'` with the comment `// Bench: was 'three' (a bare name needs an import map,
  which the CSP forbids)`.
- Nothing is uploaded. `dev.py` never writes into the opened project folder. The KiCad cache is
  `%LOCALAPPDATA%\MakerForgeBench\kicad` (or `~/.cache/maker-forge-bench/kicad`), keyed by the
  project's path and each input file's size and time, and trimmed past 500 MB.
- `kicad-cli` runs with a list of arguments (no shell), only on files inside the opened folder,
  one job at a time, with a 120-second limit.
- Converted models keep CC-BY-SA 4.0 with KiCad's exception, in `src/library/` with
  `LICENSE-KICAD-3D.md`. Bench's code stays MIT.
- Model budget: 8 MB for all of them together, 250 KB for one.
- KiCad text files are read up to 20 MB each; the bracketed-text reader's depth limit is 200.
- Your own model: a `.glb` up to 5 MB, kept in IndexedDB, not in the progress file.
- Real parts are the default (`bench.parts3d` = `"real"`). The browser test harness seeds
  `"simple"` unless a test opens with `{ realParts: true }`, so every 0.8 test keeps checking
  what it checks now.
- Copy is plain words, as in the design. `APP_VERSION` becomes `'0.9.0'` in the last task.
- After every task, `bash check.sh` must end `ALL CHECKS PASSED`. Run it in the background and
  don't edit `src/` while its browser tests run. Then commit and push.

## Review Focus

1. **Older KiCad files** (KiCad 5 `(module …)` instead of `(footprint …)`, KiCad 6–8 model
   variables): should read the same as KiCad 9. Test in Task 5.
2. **A model file that's missing or broken** (404, not a GLB): that part keeps Bench's own model,
   with no page error. Test in Task 3.
3. **Footprints turned by odd angles or on the bottom side:** pads and models land where KiCad
   puts them, the bottom mirrored. Test in Tasks 5 and 7.
4. **A project folder whose name has spaces or "ö"** handed to `kicad-cli`: it works. Test in
   Task 8.
5. **ERC positions already in millimetres** (if a later KiCad fixes the ×100 quirk): still land on
   the right symbol. Test in Task 10.

### Task 2: Matching a part to a model, and placing it

**Files:**
- Create: `src/library-match.js`, `tests/unit/library-match.test.js`

**Interfaces:**
- Consumes: `index.json` entries (Task 1).
- Produces (pure, no page code):
  - `modelFor(part, look = {}, index) -> entry | null`: `part` is a board part (`type`, `pins`,
    `mount`, `D`, `style`, `holder`, `female`, `facing`, `colour`), plus `value` from the project.
    A `look.model` or `part.model` holding a library id wins.
  - `kicadPinOrder(part) -> string[]`: Bench's pin names in KiCad pad order (diodes and LEDs:
    `K` first; electrolytics: `+`/`p` first; chips and headers by number; others in the
    project's order).
  - `placeModel(entry, holes) -> { x, y, angle, mirror, miss }`: `holes` are the part's pins in
    KiCad order as `[x, y]` mm on the board (y as `board3d` uses it). Pin 1 goes on hole 1, the
    model turned so its pin 2 points at hole 2. `miss` is the largest distance in mm between a
    placed model pin and its hole.
  - `entryForModelPath(path, index) -> entry | null`: matches `${KICAD9_3DMODEL_DIR}/LED_THT.3dshapes/LED_D5.0mm.step`
    (any `${…}` variable, `.step`/`.stp`/`.wrl`) to the entry whose `source.path` has the same
    `<folder>/<name>` without extension.
  - `MISS_LIMIT = 0.3`.

    - `outline` is `[[x, y], …]` in mm (arcs as 16 segments), or `null`;
